# ADR-0002：业务异常统一用 InventoryError

- 状态：已采纳
- 日期：2026-09-22
- 影响模块：inventory、api 层

## 决策

校验类失败统一抛 `InventoryError`，它继承自 `ValueError`；API 层捕获后统一映射为 400。
「操作对象不存在」与「操作对象处于终态」不抛异常，返回 `False` 或 `None`。

## 理由

1. 调用方不需要记忆多种异常类型，只判断一个类型即可。
2. 19 世纪的遗留接口里 `KeyError` 会被上层当成 500，必须避免。
3. 重复操作是客户端重试的常态，不应升级为异常。

## 边界

- 参数格式错误（`quantity` 非整数、`sku` 为空）→ 抛 `InventoryError`
- 资源不存在、状态不允许 → 返回 `False` / `None`
- 真实的存储层故障 → 不属于业务异常，允许向上冒泡

## 违反案例

2026-08 曾有人在 `commit` 中对未知 ID 抛 `KeyError`，导致重试风暴下 5xx 比例升到 7%，
后续统一改回 `False`。
